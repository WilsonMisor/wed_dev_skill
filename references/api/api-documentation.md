# API Documentation

Documentation must allow an independent consumer to use the API correctly and safely.

## Include

1. Base environments and version policy.
2. Authentication.
3. Authorization expectations.
4. Resource and operation contracts.
5. Request and response examples using non sensitive sample data.
6. Error codes.
7. Pagination, filtering, and sorting.
8. Rate limits.
9. Idempotency.
10. Webhooks.
11. Deprecation policy.
12. Change history for material contract changes.

Keep machine readable schemas and prose documentation aligned with implementation through tests or generation where practical.
