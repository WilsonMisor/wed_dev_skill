# Classic Theme Profile

Use when the project requires a code only WordPress classic theme.

## Requirements

1. Do not switch to a block theme or Full Site Editing without explicit scope change approval.
2. Use theme templates, template parts, hooks, WordPress APIs, PHP, HTML, CSS, and JavaScript appropriate to the approved architecture.
3. Keep business logic that should survive a theme change in plugins rather than the theme.
4. Preserve semantic HTML, accessibility, responsive behaviour, performance, SEO, and security requirements.
5. Use approved design artifacts as the visual baseline.
6. Avoid editing WordPress core.
7. Document template hierarchy and custom theme conventions.

Where the project explicitly disables Gutenberg or block editing, preserve that requirement across implementation and QA.
