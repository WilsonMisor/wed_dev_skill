# Relational Data Modeling

## Model

1. Stable primary keys.
2. Foreign keys and ownership.
3. Tenant scope where applicable.
4. Required fields and nullability.
5. Unique business constraints.
6. Check constraints for enforceable invariants.
7. Normalized transactional relationships by default.
8. Explicit lifecycle and status values.
9. Created and updated metadata where useful.
10. Audit data where required.

Use denormalization only for measured read or reporting needs with a clear synchronization strategy.
