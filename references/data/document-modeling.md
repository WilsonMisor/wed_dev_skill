# Document Data Modeling

Use document stores when aggregate access patterns and flexible nested structures justify them.

## Define

1. Aggregate boundary.
2. Identifier and tenant ownership.
3. Embedded versus referenced relationships.
4. Schema validation despite flexible storage.
5. Update atomicity.
6. Indexes for known access patterns.
7. Document growth limits.
8. Version and migration strategy.
9. Deletion and retention.
10. Cross document consistency requirements.

Do not select document storage merely to avoid designing a schema.
