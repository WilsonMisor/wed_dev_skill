# SaaS API Versioning

Define compatibility policy before external or multiple client consumers depend on an API.

## Address

1. What counts as a breaking change.
2. URL, header, schema, or capability based versioning strategy.
3. Additive change policy.
4. Deprecation notice and support window.
5. Consumer inventory.
6. Mobile client lag and old version support.
7. Database and event compatibility.
8. Contract tests across supported versions.
9. Sunset telemetry.
10. Emergency compatibility exceptions.

Do not deploy a breaking server change assuming every installed mobile client upgrades immediately.
