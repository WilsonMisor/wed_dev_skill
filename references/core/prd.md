# Product Requirements Document

The PRD defines what the product must achieve and why.

## Minimum contents

1. Context and problem.
2. Goals and non goals.
3. Users and roles.
4. Scope and release boundary.
5. User journeys and workflows.
6. Functional requirements with stable IDs.
7. Business rules with stable IDs.
8. Non functional expectations at product level.
9. Data and privacy expectations.
10. Accessibility expectations.
11. Security expectations.
12. Analytics and success metrics.
13. Dependencies and assumptions.
14. Risks and open questions.
15. Acceptance summary.
16. Approvals and baseline version.

## Requirement quality

Requirements must be testable, unambiguous, atomic enough for traceability, and written without silently embedding an implementation unless the implementation is itself a constraint.

Do not start main implementation from an unapproved or internally contradictory PRD.
