# Architecture Governance

Architecture must make system boundaries, responsibilities, state, trust boundaries, and failure behaviour explicit.

## Required decisions

1. System context and component boundaries.
2. Runtime topology.
3. Data ownership.
4. Communication patterns and contracts.
5. Authentication and authorization boundaries.
6. State management and consistency model.
7. Error and retry strategy.
8. Background processing.
9. Caching and invalidation.
10. Storage and file handling.
11. Observability.
12. Deployment topology.
13. Scaling assumptions.
14. Backup and recovery.
15. Security and privacy trust boundaries.

Use Architecture Decision Records for consequential choices. Include considered alternatives, rationale, consequences, reversibility, and triggers for reconsideration.

Architecture must be specific enough that separate agents do not invent incompatible patterns.
