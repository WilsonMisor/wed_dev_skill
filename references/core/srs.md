# Software Requirements Specification

Use an SRS when formal system behaviour, interfaces, quality attributes, or constraints need separation from product intent.

## Cover

1. System context and boundaries.
2. Actors and external systems.
3. Functional system requirements.
4. Interfaces and contracts.
5. Data requirements.
6. Security and privacy requirements.
7. Availability, reliability, performance, scalability, maintainability, portability, and recoverability requirements as applicable.
8. Accessibility requirements.
9. Logging, audit, monitoring, and support requirements.
10. Environment and deployment constraints.
11. Compliance constraints.
12. Acceptance and verification method for every requirement.

Give every requirement a stable ID and trace it to PRD intent and SRD implementation requirements.
