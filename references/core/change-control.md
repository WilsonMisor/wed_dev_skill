# Change Control

Use change control after a requirement, architecture, data contract, security model, design baseline, or release scope is approved.

## Change request

Record reason, requested change, affected baseline, requester, urgency, and desired release.

## Impact analysis

Check product scope, architecture, data model, API contracts, clients, migrations, security, privacy, accessibility, tests, operations, cost, timeline, deployment, rollback, documentation, and external consumers.

## Decision

Approve, reject, defer, or request more evidence. Approved changes receive updated baseline versions and traceability. Do not modify one downstream artifact while leaving conflicting upstream baselines unchanged.
