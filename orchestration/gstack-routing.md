# gstack Routing

gstack is the specialist engineering workforce. The AI Product Delivery Blueprint remains the governance authority.

## Default lifecycle routing

1. Discovery and reframing, use gstack office hours.
2. Product scope and value challenge, use gstack CEO review.
3. Architecture, data flow, state, edge cases, failure modes, and test planning, use gstack engineering review.
4. Design strategy and design quality, use the applicable gstack design planning and review skills.
5. Security and threat review, use gstack CSO when security review is triggered.
6. Implementation, use Codex with an approved task packet.
7. Code review, use gstack review and supply requirement IDs, architecture decisions, acceptance criteria, changed files, and tests.
8. Debugging, use gstack investigate before speculative fixes.
9. QA, use gstack QA and supply the blueprint test plan, critical paths, environments, and expected evidence.
10. Release, pass the blueprint release gate before gstack ship or equivalent release action.
11. Retrospective, use gstack retro and feed findings into maintenance, architecture decisions, tests, and future task packets.

## Separation of responsibility

gstack may challenge requirements and architecture. It may not silently change an approved baseline.

Codex may implement an approved packet. It may not expand scope without approval.

The blueprint evaluates whether required artifacts, controls, evidence, and approvals exist.

Human owners make consequential acceptance and release decisions.

## Namespacing

When gstack is installed beside other Codex skills, prefer its namespaced skill installation to avoid command collisions.
