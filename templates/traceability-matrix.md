# Traceability Matrix Template

Use one row for each requirement or controlled change.

| Requirement ID | Source | SRS ID | SRD ID | ADR or design | Data or API contract | Security or privacy control | Task packet | Code or configuration | Tests | Release evidence | Status |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | | | | | |

## Rules

1. Keep stable identifiers.
2. Mark not applicable with rationale rather than leaving critical columns ambiguous.
3. Update the matrix when requirements or implementation move.
4. Do not mark complete until required test and release evidence exists.
